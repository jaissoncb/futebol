# Entrada Kinde Test isolada

Ativada somente pelo modo Vite `kinde-dev`, usado por `pnpm dev`/`dev:frontend`/`build:dev`. O plugin troca a entrada HTML **antes** do processamento do Vite. O build padrão não utiliza esta entrada. Metadados públicos vieram do resultado Identity de 17/10/2026; não foram copiados do cliente Account.

Referência de arquitetura somente leitura: Account `authSession.ts`, `accountActions.ts`, `config.ts`, `main.tsx` e `authCallbacks.ts`. React SDK oficial 5.13.1, tokens em MemoryStorage; OAuthTransactionStorage persiste só a transação com namespace Futebol e TTL de 10 minutos. A memória nova não restaura tokens; o adapter ignora tokens persistidos antigos e destrói só seu namespace. `useInsecureForRefreshToken=false` permanece obrigatório, junto ao adapter.

Foi observado no código instalado e reproduzido em teste: o caminho login/register do SDK normaliza o redirect raiz removendo a barra final. O adaptador `kinde-authorization.ts` usa o utilitário **oficial** `generateAuthUrl` com sua opção pública `disableUrlSanitization:true`, preservando `http://localhost:5173/` tanto na autorização quanto na troca. Inclui aleatoriedade criptográfica no state serializado esperado pelo provider, sem confiar apenas no conteúdo previsível de retorno. Exige Web Crypto, usa geração S256/nonce/storage do SDK e aceita somente retornos internos conhecidos. Sem fork, patch de dependência, Client Secret ou mudança no Kinde.

O React Provider continua responsável por processar o callback/query antes de montar o HashRouter, renovar tokens em memória e executar `logout()` normal, sem allSessions. Erros OAuth, respostas implícitas, code/state ausentes ou duplicados são recusados/limpos antes do provider. Sucesso/erro não exibem parâmetros nem mensagens brutas do IdP. O botão Sair fecha/cancela o cliente HTTP antes do logout, limpa memória mesmo se houver erro e comunica somente o evento logout às outras abas Futebol. Não promete preservar SSO de outros aplicativos ou revogar JWTs instantaneamente.

Testes com classes/utilitários reais do SDK e HTTP mockado cobrem S256, state aleatório, nonce gerado (não comprovação de validação real de nonce), URI exata, troca sem secret, state/verifier inválidos antes de HTTP, replay, memória/reload, TTL, namespace Account preservado, logout e resposta tardia. Eles não substituem login/CORS/refresh/abas/PWA reais. A API permanece fechada, sem chamada ao banco; o shell autenticado não prova autorização de grupo ou principal humano.

O portal explícito `https://account.sabara.org/` gerencia conta/senha; não é issuer, proxy, callback ou backend do Futebol. Cadastro/login são hospedados no Kinde, sem formulário local de senha. Não iniciar esta entrada enquanto outro processo usar localhost:5173; não encerrar processos Identity/Account.

Diagnóstico G3 de 18/10: iniciar a entrada alternativa `pnpm dev:g3` na API e, após login Test real, clicar **Iniciar diagnóstico G3**. Bearers passam diretamente da memória SDK para `/__dev/g3`, sem decodificação, logs ou storage. São comparados access inicial, ID negativo, cache imediato e após 61 s; evento SDK `tokenRefreshed` bem sucedido fornece o access novo. Não há botão/manual refresh nem fallback se amr/auth_time faltarem. Logout local/remoto por BroadcastChannel, falha de sessão e unmount cancelam o diagnóstico. A UI mostra apenas phase/status HTTP. Este diagnóstico não permite /me/grupos e não comprova Neon. O gate de dados permanece fechado mesmo se o token isolado passar.

Após as provas reais, a entrada de dados segura usa o helper `-Mode api` descrito em api/README.md. **Verificar acesso ao Futebol** exige duas respostas /me com UUID válido e igual antes de montar a UI de grupos/jogadores/sorteio/histórico existente. Os serviços passam apenas Bearer em memória e payloads de domínio para a API; userId/role não são enviados para decidir identidade. DTOs preservam snapshots e invariantes; save mantém o mesmo UUID/payload em retry. Logout fecha o cliente retido e remove o workspace antes de navegar, inclusive quando a flag de autenticação do SDK demora a atualizar. Sem cliente/sessão Supabase simulado. O build legado mantém seu adaptador original e não é publicado por esta entrada.
